# Revisão para publicação — 11/11/2026

Escopo: arquivos que serão publicados, histórico Git, dependências JavaScript e Python, interface, API pública, acesso ao modelo e conexão ao Neon.

## Controles implementados

- Credenciais somente no ambiente do backend. `.env`, ambientes virtuais, logs, relatórios e artefatos estão ignorados. `scripts/check-secrets.py` inspeciona candidatos, staging ou histórico sem imprimir valores; também procura os segredos locais conhecidos.
- O navegador recebe apenas a URL pública da API. A chave Barô vai exclusivamente no cabeçalho Authorization da chamada do servidor ao provedor; o contexto do modelo não contém chaves ou conexões do banco.
- Validação estrita de idioma, papéis, campos, tamanhos e histórico. Pedidos em streaming são limitados pelos bytes efetivamente recebidos, independentemente de Content-Length. Somente JSON é aceito. Erros não refletem dados de entrada ou detalhes do provedor/banco.
- Limites antes da validação do corpo: 12 requisições por cliente/minuto, 100 globais/minuto e 500 em 24 horas. Três gerações simultâneas, sem fila ilimitada. Histórico e respostas não são registrados pelo backend.
- Não se confia diretamente no X-Forwarded-For recebido pela aplicação. O endereço é fornecido pelo servidor ASGI; o comportamento por cliente depende de proxies confiáveis configurados no host.
- Respostas aparecem como texto React, sem HTML ou Markdown executável. Fontes são documentos fornecidos ao modelo e links permitidos pelo aplicativo. Fontes desconhecidas, respostas inválidas e possível saída com credenciais são rejeitadas.
- API sem documentação pública e respostas sem cache. Vercel com CSP, proteção contra enquadramento, nosniff, política de referência e permissões restritas. CSS inline é necessário às animações; scripts inline executáveis não são liberados. O único hash autorizado corresponde aos dados estruturados do HTML.
- Neon: projeto dedicado, TLS com verificação de certificado/hostname e channel binding, SQL parametrizado, usuário do runtime somente com SELECT. Teste real confirmou rejeição de escrita. A publicação usa conexão administrativa separada. O LLM não possui ferramentas para executar SQL ou alterar documentos.
- Snapshots são versionados e conferidos por SHA-256 contra os documentos da versão publicada. Banco indisponível ou conteúdo divergente mantém a base aprovada incluída no código. Não há armazenamento de mensagens de visitantes no Neon.

## Verificação

`npm audit` e `pip-audit -r chatbot/requirements.txt --no-deps --disable-pip` não apontaram vulnerabilidades conhecidas nas versões fixadas após as correções. Vite e Vitest foram atualizados; dependências transitivas afetadas foram corrigidas. O override de minimatch é restrito ao typescript-estree e validado pela análise estática, preservando a API antiga usada pelo ESLint.

Testes cobrem contorno de tamanho com streaming e Content-Length falso, mídia inválida, limites antes de parsing, falsificação de cabeçalhos de IP, limite diário, contenção de gerações, CORS, erros sem dados privados, snapshots adulterados e indisponibilidade do banco. Playwright verifica respostas maliciosas tratadas como texto, links permitidos, cancelamento, idiomas, recuperação de erros e layout em desktop e celulares.

O scanner também conferiu o histórico disponível do Git (2.286 blobs), sem encontrar os padrões de credenciais procurados. Uma varredura final do staging é obrigatória antes do commit desta publicação.

## Limites da revisão

Auditoria de dependências e testes não garantem ausência de falhas. Um LLM pode errar ou desobedecer instruções; a proteção de segredos e a ausência de ferramentas de escrita não dependem apenas do prompt. Os valores de remuneração presentes na base são os autorizados para divulgação após insistência, não um mecanismo de confidencialidade no repositório público.

Contadores são locais a um worker e reiniciam com o serviço; para múltiplas instâncias, usar limites compartilhados e proteção de borda. CORS não substitui controle de abuso de uma API pública. O frontend preserva mensagens apenas na sessionStorage da aba e as envia ao provedor por meio da API para gerar respostas. Planos gratuitos podem suspender recursos após inatividade.
